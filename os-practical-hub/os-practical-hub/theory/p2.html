This practical shows how a process creates a child process and how the parent and child behave when one of them finishes first.

Key concepts

  • Process – a program in execution. Every process has a PID (process ID) and a PPID (the PID of its parent).
  • fork() – creates a new process by copying the calling process. It returns twice: 0 in the child, the child's PID in the parent, and a negative value if it fails.
  • wait() – makes the parent pause until a child terminates, then collects the child's exit status (read with WEXITSTATUS).
  • exit() – ends a process and passes an exit status to its parent.

Zombie process

A child that has finished but whose parent has not yet called wait(). The child is no longer running, but its entry stays in the process table so the parent can still read its exit status. ps shows its state as Z (defunct). Calling wait() removes ("reaps") it.

Orphan process

A child that is still running after its parent has terminated. The operating system adopts it: its PPID changes to 1 (init / systemd), which will wait for it when it ends.

What the program does

  • Option 1 – reads integers, then the parent sorts them with bubble sort while the child sorts them with selection sort; the parent calls wait() for the child.
  • Option 2 – the child exits immediately while the parent sleeps without calling wait(), so ps shows the child as a zombie.
  • Option 3 – the parent exits first while the child keeps running, so the child becomes an orphan and its PPID changes to 1.
