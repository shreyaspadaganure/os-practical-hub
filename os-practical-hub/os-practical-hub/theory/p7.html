This practical uses unnamed pipes so that a parent and child process can communicate in both directions. The parent sends a file name; the child opens the file and sends its contents back.

Key concepts

  • Pipe – a kernel buffer that lets one process write bytes and another read them in the same order (FIFO).
  • pipe(fd) – creates a pipe and fills a 2-element array: fd[0] is the read end, fd[1] is the write end.
  • Pipes and fork() – the child inherits copies of the parent's file descriptors, so both processes can use the same pipe. This is why unnamed pipes only work between related processes.
  • Half duplex vs full duplex – one pipe is one-way only. For two-way communication this program creates two pipes: p1 (parent → child) and p2 (child → parent).
  • Closing unused ends – each process closes the pipe ends it does not use. A read() returns 0 (end of file) only when all write ends are closed, so forgetting to close them can make a reader wait forever.
  • File system calls – open(), read(), write() and close() work with file descriptors, the same way for files and pipes.

Flow of the program

  1. Parent reads a file path from the user and writes it into pipe 1.
  2. Child reads the path from pipe 1 and opens the file with open().
  3. If the file cannot be opened, the child sends an error message; otherwise it reads the file and writes its contents into pipe 2.
  4. Parent reads pipe 2 and prints the contents on the screen, then calls wait() for the child.
