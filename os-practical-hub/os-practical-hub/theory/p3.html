The Producer–Consumer (bounded buffer) problem is a classic synchronisation problem. Producers put items into a fixed-size buffer and consumers take them out, at the same time.

The problems to solve

  • A producer must wait if the buffer is full.
  • A consumer must wait if the buffer is empty.
  • Only one thread may change the buffer at a time – otherwise a race condition corrupts the data.

Key concepts

  • Critical section – the part of code that accesses shared data (here the buffer and its indexes).
  • Semaphore – an integer variable changed only by two atomic operations: sem_wait() (decrement; blocks if the value is 0) and sem_post() (increment; wakes a waiting thread).
  • Counting semaphore – can hold any non-negative value, so it can count free or used buffer slots.
  • Mutex – a lock (pthread_mutex_lock / unlock) that allows only one thread inside the critical section at a time (mutual exclusion).
  • Thread – a lightweight unit of execution inside a process; threads share the same memory. Created with pthread_create and waited for with pthread_join.
  • Circular buffer – the indexes in and out wrap around using % BUFFER_SIZE.

How the solution works

  • empty_slots starts at BUFFER_SIZE (all slots free); full_slots starts at 0.
  • Producer: sem_wait(empty_slots) → lock mutex → insert item → unlock mutex → sem_post(full_slots).
  • Consumer: sem_wait(full_slots) → lock mutex → remove item → unlock mutex → sem_post(empty_slots).
  • The counting semaphore is always taken before the mutex. Reversing this order can cause a deadlock, because a thread could hold the mutex while waiting for a slot.
